Sluggish grammar -- design reference, not a parser generator input.

program        -> definition program | empty
definition     -> function | struct
struct         -> "struct" Symbol "{" members "}"
members        -> member members | empty
member         -> type Symbol ";"
function       -> type Symbol "(" arguments ")" statement
arguments      -> argument arguments_tail | empty
arguments_tail -> "," argument arguments_tail | empty
argument       -> type Symbol
type           -> Symbol pointer_tail
pointer_tail   -> "*" pointer_tail | empty

statements     -> statement statements | empty
statement      -> declaration | assignment
                | "{" statements "}"
                | "return" expression ";"
declaration    -> type Symbol initializer ";"
assignment     -> expression "=" expression ";"
initializer    -> "=" expression | empty
expression     -> unary addition_tail
addition_tail  -> "+" unary addition_tail | empty
unary          -> "&" unary | "*" unary | postfix
postfix        -> primary member_tail
member_tail    -> "." Symbol member_tail | empty
primary        -> Number | Symbol call_tail | "(" expression ")"
call_tail      -> "(" call_arguments ")" | empty
call_arguments -> expression call_arguments_tail | empty
call_arguments_tail -> "," expression call_arguments_tail | empty

Terminals:
  Symbol  = a name (TokenType::Symbol), including type, function and variable names
  Number  = a decimal integer literal (TokenType::Number)
  "="     = TokenType::EqualSign
  "+"     = TokenType::PlusSign
  "*"     = TokenType::Asterisk
  "&"     = TokenType::Ampersand
  ";"     = TokenType::Semicolon
  "{"     = TokenType::LeftBrace
  "}"     = TokenType::RightBrace
  "("     = TokenType::LeftParen
  ")"     = TokenType::RightParen
  ","     = TokenType::Comma
  "."     = TokenType::Dot
  "return" = TokenType::Return (reserved keyword)
  "struct" = TokenType::Struct (reserved keyword)

empty consumes no tokens. The program must consume the entire token sequence.

Examples:
  struct Point {
      word_16 x;
      word_16 y;
  }
  struct Line {
      Point p1;
      Point p2;
  }
  word_16 coordinates() {
      Point p;
      p.x = 4;
      p.y = 5;
      Line line;
      line.p1 = p;
      return line.p1.x + line.p1.y;
  }
  word_8 zero() { return 0; }
  word_8 example(word_8 a, word_16 b) {
      word_8 x = a;
      { word_8 x = 5; }
      x = 6;
      return x;
  }
  word_8 single(word_8 x) return x;
  word_8 constant() return 5;
  word_8 identity(word_8 x) { return x; }
  word_8 sum(word_8 a, word_8 b, word_8 c) { return a + b + c; }
  word_8 grouped(word_8 a, word_8 b, word_8 c) { return a + (b + c); }
  word_8 caller() { return identity(zero()) + identity(1); }

Pointer syntax examples (parser support only for now):
  struct Link {
      Link* next;
      word_16** data;
  }
  word_16* identity_pointer(word_16* p) return p;
  word_16 pointers(word_16* p, word_16** pp, Point* point) {
      word_16* q = &**pp;
      **pp = *identity_pointer(p) + *q;
      (*point).x = 7;
      q = &(*point).x;
      return *q;
  }

Only function and struct definitions are allowed at top level. Neither can be nested.
Struct definitions end at "}" without a trailing semicolon. Their members are
Type name declarations ending in ";", with no initializers, methods or constructors.
Types are a name followed by zero or more "*" tokens. The same type parser is used
for variables, struct members, function parameters and return types. Whitespace
around "*" is ignored; the AST records a normalized name such as "word_16**".
Member types may name other structs; the parser records these names without resolving them.
A function requires a body: one declaration, assignment, return or block statement.
Arguments are Type name pairs separated by commas. The list may be empty,
but a trailing comma, argument initializer or function prototype is not allowed.

At top level, "struct" starts a struct definition; a Symbol starts a function.
Within a statement, an initial Symbol followed by zero or more "*" tokens and
another Symbol starts a declaration. Otherwise an expression is parsed as the
assignment target, followed by "=" and the value expression.
Checking whether that target is an assignable lvalue belongs to the resolver.
An initializer is absent when the next token is ";".
"{" starts a block; its statements end at the matching "}". Blocks do not take a semicolon.
"return" starts a return statement and requires an expression followed by ";".
Only the exact names "return" and "struct" are keywords; names such as "returnValue"
and "structure" remain Symbols.
Expressions contain numbers, variable names, member access, function calls, unary
address-of and dereference operations, and additions, with parentheses for grouping.
Within an expression, a name followed by "(" starts a call; otherwise it is a variable reference.
Call arguments are comma-separated expressions. The list may be empty but cannot have a trailing comma.
Calls can appear in initializers, assignment RHSs, returns and other expressions, including call arguments.
Only named functions can be called. Standalone calls such as foo(); are not supported.
Member access is a postfix operation and binds tighter than unary operators and addition:
a.x + b.y groups as (a.x) + (b.y). Chained access a.b.c groups as (a.b).c.
Members can also be read after a call or grouped expression, such as make_point().x.
Unary "&" and "*" recursively parse another unary expression, allowing **pp, &*p,
and *get_pointer(). They bind tighter than addition: *p + x groups as (*p) + x.
Member access binds tighter: *p.x groups as *(p.x), while (*p).x selects a member
of a dereferenced value. &(*p).x takes the address of that selected member.
Assignment targets and values share the same expression tree representation.
Addition is left-associative: a + b + c builds (a + b) + c.
Each "+" wraps the accumulated expression as its left child and the next unary expression as its right.
Parenthesized expressions are parsed recursively. Unary "+" and other operators are not supported.
Initializers, assignments and returns share the same expression parser and AST types.
The parse dump parenthesizes each addition and unary operation to show its tree structure.
Only pointer parsing is implemented at this stage; pointer type checking and execution
will follow. The parser accepts syntactic expressions such as &5 or *7; deciding
whether operands have the required type or are lvalues belongs to the resolver.
Addition is resolved and lowered recursively, then executed by SimpleCPU.
Whether a name refers to a valid type or variable is checked after parsing.
The built-in types are word_8 and word_16 (unsigned 8-bit and 16-bit integers).
The resolver checks that each assigned literal fits its declared type.
Variable assignments require declared source and target variables of the same type.
Initializers, assignments and returns share expression resolution using the expected type.
Resolved expressions carry their type and a numeric value, a declaration reference,
a function reference with argument expressions, or left and right operands for addition.
Addition operands must have the same type, which is also the result type.
Only word types support addition for now; struct addition is rejected.
Literals use the expected type from the assignment, return or call argument context.
Addition results are not evaluated or checked for overflow during resolution.
Lowering emits an Add instruction with left, right and destination slots for each addition.
Literal operands are stored in temporary slots; variable operands use their existing slots.
Each addition result gets a temporary slot. Arguments, locals and temporaries share one
slot counter per function. The lower dump prints Add destination, left, right.
The CPU backend loads both operands, adds their 32-bit register values and stores the result.
Overflow handling for the narrower word_8 and word_16 types is deferred.
Duplicate declarations are rejected only within the current scope.
Variable lookup searches the current scope, then its enclosing scopes.
An inner declaration can shadow an outer name; names declared inside do not escape.
Variable declarations become visible in source order; forward references to variables are not allowed.
Initialization is not checked yet.

A function introduces a scope containing its arguments. A block body introduces
an additional nested scope. Duplicate function names and duplicate argument names
within one function are rejected. All function names, return types and argument types
are resolved before any body, allowing forward calls and recursive references.
Each resolved function keeps its arguments and flattened body separate.
Each function lowers to its own IR function with typed argument slots and one block.
SimpleCPU starts in generated _start code, which calls a zero-argument main and halts.
main writes its result starting at RAM word 0. Code starts after the full result,
with main after _start, then the remaining functions under their own entry labels.
Each invocation has a stack frame containing its arguments, locals and temporaries.
The caller passes the address of its result slot as a hidden argument, followed by
argument values in source order. The callee writes the result through that pointer
and returns to the caller, which releases the arguments and hidden pointer.
The stack grows downward, with r1 as frame pointer and r2 as stack pointer.
The SimpleCPU ISA reference defines the exact frame layout and calling convention.
Returned literals must fit the enclosing function's return type. Returned variables
are looked up in the current scope and must have exactly that return type.
Every function must contain a return. With no branches or loops, a return inside
a nested block is sufficient. Unreachable statements are not diagnosed.
Returns lower to an IR return instruction with either a literal or a source slot.
Lowering ends the function's block at the first return and emits no later statements.
The resolver still validates those later statements.
Function calls bind to a resolved function and require exactly its declared argument count.
Arguments are resolved in the caller's scope using each parameter's expected type.
The call's return type must match its surrounding expected type; no implicit conversions are allowed.
A local variable or argument shadows a function of the same name and cannot be called.
Call arguments are lowered left-to-right into slots in the caller's function.
A Call instruction stores the function name, ordered argument slots and a destination slot.
Each call gets a temporary result slot with the function's return type.
The lower dump prints Call destination, function(argument slots).
Calls execute through the SimpleCPU stack calling convention.

The resolver registers all struct names before resolving their members. Its type table
looks up both built-in words and structs, and each struct keeps its members in declaration order.
Duplicate type names (including built-in names), duplicate members, unknown member types,
and direct or indirect recursive containment by value are rejected.
Structs may refer to other structs defined later, and may reuse the same member type.
Function signatures and local variables use this same type lookup.
Member access resolves the object's type, then binds to a member index in that type.
The member's declared type becomes the expression's type. Unknown members and member
access on a word are rejected. Chained members are resolved from the object outward.

Assignment.target contains the full expression and resolves to a typed lvalue.
Variables are lvalues; a member is an lvalue only when its object is one.
Members of function-call results may be read, but cannot be assigned to.
Numbers, additions and function-call results are not assignment targets.
The RHS must have exactly the target's type, including for whole-struct copies.
Different named structs remain distinct types even when their members match.
Struct initializers may copy existing values; no constructors or default initialization
are generated. Struct arguments and returns use the same exact type checks.

The resolver's type table owns struct types. compile() moves that table into the returned
IRProgram alongside its functions, keeping the IR's type references valid.
Member access lowers to a Member instruction containing a source slot, member index
and destination slot. The destination aliases storage inside the source; it does not
allocate new storage. Nested member access lowers one member at a time.
The lower dump prints Member destination, source, member_index.
The backend determines member offsets from the source slot's type. SimpleCPU stores
each scalar in one RAM word and struct fields consecutively in declaration order.
Empty structs occupy one word. Copies, arguments and returns copy all words by value.
