Sluggish grammar -- design reference, not a parser generator input.

program        -> function program | empty
function       -> Symbol Symbol "(" arguments ")" statement
arguments      -> argument arguments_tail | empty
arguments_tail -> "," argument arguments_tail | empty
argument       -> Symbol Symbol

statements     -> statement statements | empty
statement      -> Symbol statement_tail
                | "{" statements "}"
                | "return" expression ";"
statement_tail -> Symbol initializer ";"
                | "=" expression ";"
initializer    -> "=" expression | empty
expression     -> primary addition_tail
addition_tail  -> "+" primary addition_tail | empty
primary        -> Number | Symbol | "(" expression ")"

Terminals:
  Symbol  = a name (TokenType::Symbol), including type, function and variable names
  Number  = a decimal integer literal (TokenType::Number)
  "="     = TokenType::EqualSign
  "+"     = TokenType::PlusSign
  ";"     = TokenType::Semicolon
  "{"     = TokenType::LeftBrace
  "}"     = TokenType::RightBrace
  "("     = TokenType::LeftParen
  ")"     = TokenType::RightParen
  ","     = TokenType::Comma
  "return" = TokenType::Return (reserved keyword)

empty consumes no tokens. The program must consume the entire token sequence.

Examples:
  word_8 zero() { return 0; }
  word_8 example(word_8 a, word_16 b) {
      word_8 x = a;
      { word_8 x = 5; }
      x = 6;
      return x;
  }
  word_8 single(word_8 x) return x;
  word_8 constant() return 5;
  word_8 identity(word_8 x) { return x; }
  word_8 sum(word_8 a, word_8 b, word_8 c) { return a + b + c; }
  word_8 grouped(word_8 a, word_8 b, word_8 c) { return a + (b + c); }

Only function definitions are allowed at top level. Functions cannot be nested.
A function requires a body: one declaration, assignment, return or block statement.
Arguments are Type name pairs separated by commas. The list may be empty,
but a trailing comma, argument initializer or function prototype is not allowed.

LL(1): top level always expects a function. Within a statement, after the first
Symbol, another Symbol starts a declaration;
"=" starts an assignment. An initializer is absent when the next token is ";".
"{" starts a block; its statements end at the matching "}". Blocks do not take a semicolon.
"return" starts a return statement and requires an expression followed by ";".
Only the exact name "return" is a keyword; names such as "returnValue" remain Symbols.
Expressions contain numbers, variable names and additions, with parentheses for grouping.
Addition is left-associative: a + b + c builds (a + b) + c.
Each "+" wraps the accumulated expression as its left child and the next primary as its right.
Parenthesized expressions are parsed recursively. Unary "+" and other operators are not supported.
Initializers, assignments and returns share the same expression parser and AST types.
The parse dump parenthesizes each addition to show its tree structure.
Addition is resolved and lowered recursively, then executed by SimpleCPU.
Whether a name refers to a valid type or variable is checked after parsing.
The built-in types are word_8 and word_16 (unsigned 8-bit and 16-bit integers).
The resolver checks that each assigned literal fits its declared type.
Variable assignments require declared source and target variables of the same type.
Initializers, assignments and returns share expression resolution using the expected type.
Resolved expressions carry their type and a numeric value, a declaration reference,
or left and right operands for addition.
Addition operands must have the same type, which is also the result type.
Literals use the expected type from the assignment or return context.
Addition results are not evaluated or checked for overflow during resolution.
Lowering emits an Add instruction with left, right and destination slots for each addition.
Literal operands are stored in temporary slots; variable operands use their existing slots.
Each addition result gets a temporary slot. Arguments, locals and temporaries share one
slot counter per function. The lower dump prints Add destination, left, right.
The CPU backend loads both operands, adds their 32-bit register values and stores the result.
Overflow handling for the narrower word_8 and word_16 types is deferred.
Duplicate declarations are rejected only within the current scope.
Variable lookup searches the current scope, then its enclosing scopes.
An inner declaration can shadow an outer name; names declared inside do not escape.
Declarations become visible in source order; forward references are not allowed.
Initialization is not checked yet.

A function introduces a scope containing its arguments. A block body introduces
an additional nested scope. Duplicate function names and duplicate argument names
within one function are rejected. Return and argument types are resolved before
the body. Each resolved function keeps its arguments and flattened body separate.
Each function lowers to its own IR function with typed argument slots and one block.
SimpleCPU executes a zero-argument main, placing its return value in r0 and halting.
Other functions are checked by the compiler but are not emitted by the CPU backend yet.
Returned literals must fit the enclosing function's return type. Returned variables
are looked up in the current scope and must have exactly that return type.
Every function must contain a return. With no branches or loops, a return inside
a nested block is sufficient. Unreachable statements are not diagnosed.
Returns lower to an IR return instruction with either a literal or a source slot.
Lowering ends the function's block at the first return and emits no later statements.
The resolver still validates those later statements.
Function calls are not supported yet.
